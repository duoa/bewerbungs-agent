# Implementation Plan: Langfuse Observability for the Application Pipeline

**Branch**: `006-langfuse-observability` | **Date**: 2026-05-13 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/006-langfuse-observability/spec.md`

## Summary

Add a single internal observability wrapper that emits one Langfuse trace per CLI run with one nested span per pipeline stage. The wrapper has two implementations behind one Protocol — a `NoOpObservability` (immediate return on every call, no Langfuse import) and a `LangfuseObservability` backed by the official `langfuse` Python SDK. Selection happens once at CLI start based on `observability.langfuse.enabled` plus presence of `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` env vars; missing credentials silently degrade to no-op. Stage functions stay untouched at the signature level; the graph wires a `with observability.stage_span(...)` context manager around each node invocation. Default payload mode is summary-only; raw payloads gate behind `log_full_inputs` / `log_full_outputs`; a credential + PII redaction filter runs on every outbound field regardless of mode. MLflow integration is unchanged; when both are active, the Langfuse trace ID and URL are written as MLflow tags one-way. Flush is bounded to 3s at CLI exit (FR-020).

## Technical Context

**Language/Version**: Python 3.11 (matches `pyproject.toml`, mypy strict)
**Primary Dependencies**: `langfuse>=2.0` (new); existing `langgraph>=0.2`, `pydantic>=2.0`, `anthropic>=0.25`, `mlflow>=3.11.1`, `typer>=0.12`
**Storage**: File artifacts under `outputs/<run_id>/` unchanged; Langfuse traces are stored in the operator-provided Langfuse instance (cloud or self-hosted via `LANGFUSE_BASE_URL`). No new local storage.
**Testing**: `pytest>=8.0`, `pytest-mock>=3.0` (existing). New unit tests under `tests/unit/test_observability.py`; integration test extension in `tests/integration/test_full_run.py`.
**Target Platform**: macOS / Linux CLI; Python 3.11. Same as the rest of the project.
**Project Type**: Single-project CLI (Option 1).
**Performance Goals**: Per-span overhead ≤ 50 ms wall-clock when enabled; ≤ 1 ms when disabled (no-op branch must not allocate). Flush at exit ≤ 3 s hard bound (FR-020).
**Constraints**:
- `letter.md` and every `artifacts/*.json` MUST be byte-identical between enabled and disabled runs on the same inputs (FR-013, SC-004).
- MLflow integration MUST remain untouched in behaviour (FR-014).
- A Langfuse SDK or network failure MUST NOT abort the pipeline (FR-015).
- Credential / PII redaction MUST run before every Langfuse network call (FR-017, FR-019a).
- The CLI MUST flush within 3 s at exit (FR-020).

**Scale/Scope**: One process per invocation; ~12 stage spans per typical run (extract → load → select → evidence → plan → write‖tailor → review → targeted_rewrite → validate [+rewrite]); ~3 nesting depth (trace → branch siblings → no deeper).

**Structure Decision**: Reuse the existing single-project layout (`src/bewerbungs_agent/`). The observability wrapper is one cohesive module (`utils/observability.py`) with helper modules `utils/redaction.py` and `utils/summaries.py` to keep the wrapper focused. The decision to NOT touch stage modules preserves Principle V (deterministic typed interfaces stay unchanged) and minimizes diff footprint — the entire feature lives behind the graph wiring layer.
